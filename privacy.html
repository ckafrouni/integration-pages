Policy / Privacy

Data, with context.

How authorized personal data may be used by Executor Personal, and how this public documentation site differs from the private runtime.

Last updated 14 October 2026.

01 / Operator and purpose

Executor Personal is operated by Christophe Kafrouni for personal use. It is a private, self-hosted integration layer supporting authorized personal AI-assisted workflows, not a public SaaS service or a Zentio offering.

The operator controls the self-hosted runtime and handles data and deletion requests through existing private communication channels.

02 / Authorization and data access

OAuth access depends on the scopes granted by the account holder. Depending on those scopes and the provider’s rules, Executor Personal can read, search, or manage authorized email, files, calendars, contacts, documents, spreadsheets, and tasks.

Authorized workflows may process relevant content, metadata, and results needed for the requested task. Listing an integration or product does not imply that access is granted. Google is currently being configured; Microsoft is future planned and not live.

03 / Storage and retention

OAuth tokens are stored encrypted in Executor. The runtime is self-hosted and operator-controlled. These statements do not imply that all data stores or backups have the same encryption properties.

Authorized data and results may be persisted in task histories, logs, or backups, depending on configuration. No exact retention schedule has been verified. The operator manages retention and deletion, including local stores and any relevant histories, logs, or backups.

Records retained by Google, Microsoft, GitHub, or other providers are subject to those providers’ own policies and controls.

04 / Optional AI processing

AI-assisted summaries or workflows may share relevant authorized data with configured agent or model providers for the requested processing. No definitive provider list, zero-data-retention setting, or no-training setting has been verified here.

Do not interpret this documentation as a guarantee that every provider retains nothing or has disabled training. Provider processing must remain consistent with the source provider’s applicable restrictions and the account holder’s authorization.

05 / Disclosure and use restrictions

Disclosure is limited to operator-authorized service processing, security needs, or legal requirements. Authorized personal data is not published as public datasets or made publicly available.

Use of Google user data is subject to the Google API Services User Data Policy, including Limited Use. Under that policy, selling Google user data, using it for advertising, or using it for general-purpose model training is not permitted. This is a restriction on data use, not a claim of verified zero retention across providers.

06 / Revocation and deletion

The account holder can revoke provider permissions through the provider’s account controls. Revocation does not automatically delete previously saved data, task histories, logs, or backups.

For deletion, contact the operator privately. The operator handles deletion across operator-controlled stores, including local stores, and considers relevant histories and backups. No fixed deletion timeline is promised here. Provider-held records remain subject to provider policies and available controls.

Do not include account data, tokens, or other sensitive material in public GitHub issues. See contact and deletion request guidance.

07 / This public website

This is a static documentation site. It has no application login and does not process connected-account data or execute workflows. No analytics or tracking have been added to the site.

GitHub, as the hosting provider for GitHub Pages, may log visitor IP addresses and security-related data under the GitHub Privacy Statement.

08 / Updates and questions

This policy should be updated when integrations or processing practices change. The date above identifies this version. For private account or deletion questions, use an existing private communication channel with Christophe Kafrouni. For documentation corrections, use the public documentation contact options.
